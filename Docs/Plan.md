# Plan: Birdy

A believable B2B collaborative-work app that stands in for a client codebase. Starlings ports
it into the prototyping kit to work out skills and best practices for building on top of a
real product.

- **The client:** Birdy, Inc., a hypothetical SaaS company that makes **Birdy**.
- **The product:** Birdy is a task-first workspace for company teams: tasks, files and
  folders, sharing, and an AI assistant.
- **The demo tenant:** the seeded workspace belongs to **Meridian Outdoor Co.**, a Birdy
  customer (an outdoor-gear maker getting ready for its Spring '27 catalog launch). Their
  people, teams, tasks and files are the data the prototype runs on.

## 1. Goals and non-goals

**Goals**
- Feel like a real mid-market SaaS frontend: typed API client, server-state caching, routing,
  a component library, feature folders, lint and tests.
- Task-first landing experience. Files and folders come second.
- An AI assistant that answers questions about tasks, files and priorities from the seeded
  data, with citations back into the app.
- The backend runs in the browser behind a real HTTP boundary.
- Clean seams for a mobile app later (shared domain types and API client).

**Non-goals (for now)**
- A real backend, auth, file storage or LLM calls.
- Real-time multi-user sync.
- Storybook and a mobile app.

## 2. Architecture

```
┌──────────────────────────── Browser ────────────────────────────┐
│  React UI (routes → features → components/ui)                    │
│        │  hooks: useTasks(), useFolder(), useAssistant() …       │
│  TanStack Query  ── caching, optimistic updates, invalidation    │
│  api/client.ts   ── typed fetch wrapper                          │
│        │  fetch('/api/v1/…')                                     │
│ ═══════╪═════════════ HTTP boundary (looks real) ═══════════════ │
│  MSW (Mock Service Worker) request handlers                      │
│  Mock DB (in-memory, persisted to localStorage, seeded)          │
│        +  Assistant engine (simulated, streamed responses)       │
└──────────────────────────────────────────────────────────────────┘
```

**Tokens:** there is no Figma library file yet, so the token source is authored by hand in
Figma's variables-export JSON format (`Color` collection with Light and Dark modes, plus a
`Primitives` collection). The kit's `tokens` command converts it to CSS with the alpha
transform and regression guard. When a real Figma export arrives, it replaces the
hand-authored files and nothing downstream changes.

### Demo panel

A floating **Demo** control that ships with the prototype (it's part of the test bed, not a
sandbox page):
- **Persona:** sign in as any seeded user (admin, team lead, member, guest).
- **Network:** add latency (0 / 400 / 1500 ms), or make every request fail.
- **Data:** reset to the seed, or switch to an empty workspace.

## 3. Domain model

```
Organization ─┬─< User (role: admin | member | guest)
              ├─< Team ──< TeamMembership (lead | member) >── User
              ├─< Project (name, team, color, root folder)
              ├─< Task ──< Comment, ActivityEvent, linked File ids
              ├─< Folder (tree via parentId) ──< File
              ├─< ShareGrant (resource: folder|file, principal: user|team, level: view|edit)
              │     + generalAccess on each folder/file: restricted | org-view | org-edit
              └─  Assistant messages (streamed, with citations)
```

**Seed:** Meridian Outdoor Co., 18 people in 4 teams (Product Design, Engineering, Marketing,
Operations), 3 projects (Spring '27 Catalog, Checkout Redesign, Supplier Portal), about 45
tasks spread across overdue, today, this week and later, and about 35 files in about 12
folders. The briefs, research notes, plans, specs and meeting notes contain real text. All
dates are relative to the day the data is seeded, and they shift forward with the calendar so
the demo never goes stale.

## 4. Visual system

The color comes from the Starlings palette (light = "drawing office", dark = "field at
dusk"), mapped to app semantics:

| Token (`--bd-color-…`) | Light | Dark | Use |
| --- | --- | --- | --- |
| `bg-app` | `#f6f2ea` | `#15141e` | Page background |
| `bg-raised` | `#fffdf8` | `#1f1c29` | Cards, sidebar, panels, dialogs |
| `border-default` | `#ddd6c9` | `#352f42` | Every raised surface and control |
| `text-default` / `text-muted` | `#1d1b22` / `#5e5966` | `#f2e9da` / `#ada4af` | |
| `action-bg` / `action-text` | ink / paper | apricot / dusk | Primary button, one per view |
| `focus-ring` | teal | teal | 2px focus outline |
| `status-done` | teal | teal | Done |
| `status-progress` | sky | sky | In progress |
| `status-review` | violet | violet | In review |
| `warning` | amber | amber | Due soon, high priority |
| `ai` | violet | violet | Everything assistant-related |
| `danger` | rust `#a63d2a` | `#f08a7a` | Overdue, urgent, destructive (new) |

**Type:** Bricolage Grotesque is the display face (page titles, section headers, greeting,
big numbers). Instrument Sans is the utility face (everything else).
**Shape:** 6px radius for controls, 10px for cards, 14px for panels, and pills for chips. A
1px border on raised surfaces. Spacing is on a 4px scale. Density is compact (36px controls,
14px base text).

## 5. App shell

- **Sidebar:** workspace name · Home · My tasks · Files · Shared with me · People · Teams
  (list) · Projects (list). User menu at the bottom (profile, theme, sign out).
- **Top bar:** search / ⌘K, a "New" menu (task, folder, upload), and the **Ask Birdy** button
  (⌘J).
- **Right side:** the task drawer, the file drawer and the assistant panel slide in over the
  page. The open drawer is kept in the URL (`?task=` / `?file=`) so it can be deep-linked.

## 6. Workflows

★ = core build. Unstarred items are stretch.

**A. Entry and identity**
1. ★ Sign in (simulated): pick a person from Meridian.
2. ★ Switch persona from the demo panel.

**B. Home: "My work"**
3. ★ Daily triage: greeting, an AI focus card (top 3 with reasons), and my tasks grouped
   Overdue · Today · This week · Later. Check a task off with an undo toast.
4. ★ Quick add with simple syntax: `Draft hero copy tomorrow !high @maya`.
5. ★ Secondary column: recent files, shared with me, and my teams with open-task counts.

**C. Tasks**
6. ★ Browse and filter (status, priority, assignee, due), grouped by status, with filters
   kept in the URL.
7. ★ Task drawer: inline edits, status, assignee, priority, due date, linked files, comments,
   activity.
8. ★ New task dialog.
9. Board view and bulk actions (stretch).

**D. Files and folders**
10. ★ Browse: folder tree, breadcrumbs, list and grid views, sorting.
11. ★ File drawer: preview, details, linked tasks, who has access, "Ask about this file".
12. ★ New folder, simulated upload, rename, move, star, and delete with undo.
13. ★ Shared with me, Starred, Recent.
14. ★ Link files and tasks from either side.

**E. Sharing and permissions**
15. ★ Share dialog: people and teams with view or edit access, general access, copy link.
16. ★ Permission-aware UI: controls are disabled with a reason, and guests see only what's
    shared with them.

**F. Org, teams, people**
17. ★ People directory and profiles.
18. ★ Team pages. Admins and leads manage members and create teams.
19. Org settings (stretch). Profile and appearance settings are core.

**G. Ask Birdy (AI)**
20. ★ Panel from anywhere, with suggested prompts that depend on the current page.
21. ★ Streamed answers with citation chips that open the cited task or file.
22. ★ Scoped context chip (this file / this task / this team), removable.
23. Create tasks from answers, and thread history (stretch).

**H. Cross-cutting**
24. ★ ⌘K search across tasks, files, people, teams and projects, plus quick actions.
25. ★ Loading, empty and error states, all triggerable from the demo panel.
26. ★ Light and dark themes.
27. Notifications (stretch).
