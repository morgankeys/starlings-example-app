# Architecture

How the Birdy web app works and how to work with it. Written for agents and the project's
owner. Verify claims against the code before relying on them.

## TL;DR

- Vite + React 18 + TypeScript (strict). React Router 6, TanStack Query 5, Radix UI
  primitives, CSS Modules, lucide-react icons.
- The backend is **simulated in the browser**: MSW intercepts `fetch('/api/v1/…')` and
  answers from a seeded in-memory database persisted to `localStorage`. The app code
  doesn't know it's talking to a mock.
- Styling is **token-only**: every color, space, radius and type value is a `--bd-*`
  custom property from `src/styles/tokens.generated.css`. Never hand-edit that file.
- Commands: `npm run dev`, `npm run build`, `npm run lint`, `npm run check`,
  `npm run validate`, `npm test` (see `README.md`).

## Project structure

```
Code/
  index.html                 Fonts (Google Fonts) and the root element
  public/
    mockServiceWorker.js     GENERATED by MSW. Do not edit.
  scripts/
    tokens.mjs               `tokens`: unpack Figma exports, write token CSS (alpha-preserving)
    check-alpha.mjs          Alpha regression guard (runs in `build`)
    check-dev-pages.mjs      Dev-only pages guard (runs in `build`)
    ds-validate.mjs          `validate`: design-system validator and backlog writer
    lib/tokens-source.mjs    Shared reader for the token JSON
  src/
    main.tsx                 Starts the mock backend, then renders <App>
    app/                     Providers, router, AppShell, Sidebar, TopBar, DemoPanel,
                             session (RequireSession, useSession), theme, panels (URL state)
    routes/                  One folder per page; dev/ holds dev-only pages
    features/                Domain slices: components + hooks per area
      tasks/ files/ sharing/ org/ assistant/ search/
    components/
      ui/                    Design-system primitives (Button, Menu, Dialog, SidePanel, …)
      brand/                 Logo
    api/                     client.ts (fetch wrapper), endpoints.ts, keys.ts
    domain/types.ts          Types shared by the app and the mock backend
    mocks/                   The simulated backend (see Agents/context/mock-backend.md)
    styles/
      tokens.generated.css   GENERATED by `tokens`. Do not edit.
      global.css             The one global stylesheet: resets and element defaults
    lib/                     Small utilities (dates)
    test/setup.ts            Vitest setup
```

**Dependency direction:** `routes → features → components/ui`. `api`, `domain` and `lib`
are shared by everything. Only `main.tsx` imports from `mocks/` (plus tests that use the
seed). `features/*` may use each other's components (the task panel shows file icons), but
`components/ui` never imports from `features`.

### Data flow

1. A component calls a feature hook (`useTasks`, `useFolder`, `useUpdateTask`, …).
2. The hook uses TanStack Query with a key from `api/keys.ts` and a function from
   `api/endpoints.ts`.
3. `api/client.ts` calls `fetch('/api/v1/…')` and throws `ApiError` on non-2xx.
4. MSW answers from `src/mocks/handlers/*`, which read and write `src/mocks/db.ts`.

Mutations invalidate by key prefix (`['tasks']`, `['files']`, `['folders']`, `['teams']`).
Task updates are optimistic (`patchTaskCaches` in `features/tasks/api.ts`). Completing a
task goes through the query client rather than a component-scoped mutation, because the
row usually disappears from its list before the request finishes, and TanStack Query
drops per-call callbacks once the calling component unmounts.

### URL state

- Task and file details open in a right-hand `SidePanel` driven by `?task=<id>` and
  `?file=<id>` (`app/panels.ts`), so any page can show them and links are shareable.
- Task list filters live in the URL too (`?status=…&priority=…&due=…&q=…&group=…`).
- `?view=board` switches `TasksView` from the grouped list to the kanban board
  (`features/tasks/TaskBoard.tsx`); absent means list. `group` only applies to the list.
  The board has one column per status (`boardColumns` in `grouping.ts`), narrowed by the
  status filter and without Done when the view's base filters set `includeDone: false`.
  Cards move between columns by native HTML5 drag and drop (a `useUpdateTask` status patch,
  optimistic, with a toast on error) or with the "Move to…" `StatusMenu` on each card,
  which is the keyboard and touch alternative.

### Ask Birdy

`features/assistant/AssistantProvider.tsx` holds the conversation, the open state and the
**context** (what the user is looking at). Pages call
`useAssistantContext({ type, id, label })`; panels register in a higher-priority slot.
`askAbout(context, question)` opens the panel scoped to something. Answers stream from
`POST /api/v1/assistant/messages` as `text/event-stream` (`data: {json}` events: `token`,
`citations`, `done`). Citation tokens like `[[task:t_123]]` in the text become clickable
chips (`MessageContent.tsx`).

## Styling rules

- **Namespace:** `--bd-*`. Groups: `--bd-color-*` (themed: light on `:root`, dark on
  `[data-theme='dark']` and `prefers-color-scheme: dark`), `--bd-space-*`, `--bd-radius-*`,
  `--bd-font-family-*`, `--bd-font-size-*`, `--bd-font-weight-*`, `--bd-font-line-height-*`,
  `--bd-font-letter-spacing-*`, `--bd-size-*` (controls, icons, avatars, layout widths),
  `--bd-duration-*`. Grep `src/styles/tokens.generated.css` for exact names.
- **Scoped styles only.** Each component has a `*.module.css` next to it. `global.css`
  holds element selectors only (no classes), plus shared keyframes (`bd-*`).
- **No inline `style` props.** Variants are `data-*` attributes on the component root
  (`data-variant`, `data-size`, `data-tone`, …) with attribute selectors in the module.
  Every primitive also carries `data-component="<Name>"`.
- **Theme:** `app/theme.ts` sets `data-theme` on `<html>` (or removes it for "system").
- **Elevation:** borders, not shadows. The one exception is floating layers (menus,
  popovers, dialogs, docked panels on small screens), which use
  `box-shadow: 0 … var(--bd-color-shadow-overlay)`.
- **Animations** on Radix content run only in the open state (`[data-state='open']`).
  Radix keeps closed content mounted while an animation is running, which left menus
  stuck open behind dialogs. Menus are also non-modal, and menu item actions run after
  the menu has closed.

## Validation

- **Stylelint** (`.stylelintrc.json`): `stylelint-config-standard`,
  `stylelint-config-css-modules`, and `stylelint-declaration-strict-value` forcing
  `var(…)` for color, background, font, spacing and radius properties. Custom properties
  must match `--bd-*`. The generated token CSS is ignored.
- **Validator** (`scripts/ds-validate.mjs`) implements the contract in
  `Docs/Design system/design-in-code architecture.md`, with these rule ids:
  `hardcoded-color`, `raw-spacing`, `raw-border-radius`, `non-token-font-family`,
  `raw-font-size`, `raw-typography`, `non-token-variable`, `local-token-override`,
  `unscoped-style`, `global-component-leak`, plus **`inline-style`** (a `style={{…}}` prop
  in a `.tsx` file).
  - Allowed values: `0`, `inherit`, `initial`, `unset`, `revert`, `normal`, `none`,
    `auto`, `transparent`, `currentcolor`.
  - Exempt: `src/styles/tokens.generated.css`.
  - Component style blocks are found by file name: `*.module.css` is scoped;
    `src/styles/global.css` is the global stylesheet; any other `.css` is `unscoped-style`.

## Dev-only pages guard

- Dev-only pages live in `src/routes/dev/` and nowhere else. `app/router.tsx` adds the
  `/dev/*` route inside `if (import.meta.env.DEV)` with a lazy import, so Vite drops the
  module from production builds.
- Every dev page module exports the marker `BIRDY_DEV_ONLY_PAGE`.
  `scripts/check-dev-pages.mjs` runs at the end of `build` and fails if `dist/` contains a
  `dev/` folder or any file containing the marker. (Verified: forcing the dev route into a
  build makes the guard exit 1.)
- Sample people in `ComponentSpecimens.tsx` are fictional and only render there.
- The Demo panel is **not** a dev-only page: it ships with the prototype on purpose,
  because it's how the test bed gets demoed.

## Build & dev workflow

`npm run build` runs, in order:

1. `tokens`: unpack any `*.zip` in `Docs/Design system/Figma tokens/`, then write
   `tokens.generated.css` (only if it changed).
2. `check-alpha.mjs`: every source color with `alpha < 1` must be emitted with an alpha
   channel.
3. `tsc -b`: type check.
4. `vite build` → `dist/` (vendor chunks: react, query, radix, msw, icons).
5. `check-dev-pages.mjs`.

Typical loops:

- **After a token change:** `npm run tokens`, `npm run build`, `npm run validate`, review
  the backlog diff.
- **Before committing component changes:** `npm run lint`, `npm run check`,
  `npm run validate`, `npm test`.

## Maintenance

- **Adding a UI primitive:** create `Name.tsx` + `Name.module.css` in `components/ui/`, add
  `data-component` and `data-*` variant attributes, export it from `components/ui/index.ts`,
  and add a specimen to `routes/dev/ComponentSpecimens.tsx`.
- **Adding an endpoint:** add the handler in `src/mocks/handlers/`, the function in
  `api/endpoints.ts`, a key in `api/keys.ts` and a hook in the feature's `api.ts`.
- **Changing seed data:** edit `src/mocks/seed/`. Bump `DB_VERSION` in
  `src/mocks/seed/index.ts` when the stored shape changes, so old browsers reseed.
- **Working down the backlog:** see `Agents/context/design-system.md`.
- When this file changes, check `Code/README.md`, `Agents/context/design-system.md` and
  `Agents/context/mock-backend.md` for drift.
